# Students Database CRUD API

A Python backend to manage student records with **Create, Read, Update and Delete** operations.
Built with **FastAPI** and **SQLite** for the EWB Edu Tech internship assignment, plus the
**optional bonus**: ask natural-language questions about the data using a local **Ollama** model.

## Features

- Full CRUD on students: `POST`, `GET` (list + single), `PUT`/`PATCH`, `DELETE`
- Persistent storage in a SQLite file (`students.db`, created automatically)
- Input validation (email format, phone format, date of birth in the past, at least one contact field)
- Clear error handling: `404` missing record, `409` duplicate email, `422` invalid input
- Filtering and pagination on the list endpoint
- Interactive API docs (Swagger UI) at `/docs`
- 40+ automated tests (`pytest`)
- Optional: `/ai/ask` endpoint using Ollama, grounded in retrieved records (no model-generated SQL)

## Tech stack

Python 3.10+ · FastAPI · SQLAlchemy 2 · SQLite · Pydantic v2 · Uvicorn · pytest · httpx


## Student record fields

| Field             | Required | Notes                                              |
|-------------------|----------|----------------------------------------------------|
| `id`              | auto     | Unique student ID, generated by the database       |
| `name`            | yes      | 1-100 characters                                   |
| `date_of_birth`   | yes      | `YYYY-MM-DD`, must be in the past                  |
| `email`           | see note | Valid email, unique (case-insensitive)             |
| `phone`           | see note | 7-20 chars: digits, spaces, `-`, `()`, optional `+` |
| `course`          | no       |                                                    |
| `address`         | no       |                                                    |
| `enrollment_date` | no       | `YYYY-MM-DD`                                       |

> **Note:** at least one of `email` or `phone` is required.

## API endpoints

| Method        | Endpoint                | Purpose                          | Success |
|---------------|-------------------------|----------------------------------|---------|
| POST          | `/students`             | Create a student                 | 201     |
| GET           | `/students`             | List / filter students           | 200     |
| GET           | `/students/{student_id}`| View one student                 | 200     |
| PUT           | `/students/{student_id}`| Replace a student (all fields)   | 200     |
| PATCH         | `/students/{student_id}`| Update only the fields you send  | 200     |
| DELETE        | `/students/{student_id}`| Delete a student                 | 204     |
| POST          | `/ai/ask`               | (Optional) Ask a question        | 200     |
| GET           | `/health`               | Health check                     | 200     |

### List filters (query parameters for `GET /students`)

| Parameter     | Meaning                                              |
|---------------|------------------------------------------------------|
| `name`        | Case-insensitive "contains" match                    |
| `course`      | Exact course (case-insensitive)                      |
| `email`       | Exact email (case-insensitive)                       |
| `born_after`  | Date of birth strictly after `YYYY-MM-DD`            |
| `born_before` | Date of birth strictly before `YYYY-MM-DD`           |
| `skip`, `limit` | Pagination (default `0` / `100`, max limit `500`)  |

The total number of matches is returned in the `X-Total-Count` response header.

### Error responses

| Status | When                                                              |
|--------|-------------------------------------------------------------------|
| 404    | Student ID does not exist                                         |
| 409    | Email already used by another student                             |
| 422    | Invalid input (bad email/phone/date, missing fields, no contact)  |
| 503    | (AI endpoint only) Ollama not running or model not downloaded     |

## Testing the API with sample requests

Create a student:

```bash
curl -X POST http://127.0.0.1:8000/students \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Aarav Sharma",
    "date_of_birth": "2004-08-15",
    "email": "aarav.sharma@example.com",
    "phone": "+91 90000 00001",
    "course": "Computer Science",
    "address": "Mumbai, Maharashtra",
    "enrollment_date": "2022-07-01"
  }'
```

List all, filter, and view one:

```bash
curl http://127.0.0.1:8000/students
curl "http://127.0.0.1:8000/students?course=Computer%20Science&born_after=2005-01-01"
curl "http://127.0.0.1:8000/students?name=aarav"
curl http://127.0.0.1:8000/students/1
```

Update (partial) and replace (full):

```bash
curl -X PATCH http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" \
  -d '{"course": "Electronics"}'

curl -X PUT http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" \
  -d '{"name": "Aarav Sharma", "date_of_birth": "2004-08-15", "email": "aarav.sharma@example.com"}'
```

Delete:

```bash
curl -X DELETE http://127.0.0.1:8000/students/1      # 204 No Content
curl http://127.0.0.1:8000/students/1                # 404 Not Found
```

> Windows PowerShell users: use `curl.exe` instead of `curl`, or simply use the Swagger UI at
> `/docs`, which needs no command line.

## Optional bonus: local AI with Ollama

This part is optional; the core CRUD app works without it.

### Setup

```bash
# 1. Install Ollama from https://ollama.com/download, then download a small model
ollama pull llama3.2:1b

# 2. Make sure the Ollama server is running (it usually starts automatically)
ollama serve

# 3. Start this API (in another terminal) and add some data
python seed.py
uvicorn app.main:app --reload
```

### Ask questions

```bash
curl -X POST http://127.0.0.1:8000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "How many students are there?"}'

curl -X POST http://127.0.0.1:8000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "List students born after 2005"}'
```

Example response fields: `answer`, `model`, `filters_applied`, `total_students`, and
`records_used` (the exact records the answer was based on, so you can verify it).

Questions the retrieval step understands:

- counts: "How many students are there?"
- birth year: "List students born after 2005", "born before 2004", "born in 2006"
  ("born after 2005" means born in 2006 or later)
- course: "How many students study Electronics?"
- a student's name: "What is Diya Patel's course?"
- anything else falls back to giving the model all students (up to 50) as context

### How the AI stays accurate and safe

1. **Backend code retrieves the records**, using simple parsing rules and normal parameterised
   ORM queries. The model never writes or runs SQL.
2. Only the retrieved records, plus exact facts such as the total count, are placed in the prompt.
3. The system prompt tells the model to answer **only** from that context and to say so when
   the answer is not in the records. Temperature is 0 for consistent answers.
4. If Ollama is not running or the model is missing, the endpoint returns a clear `503` message.

## Architecture overview (for the demo)

- **Routers** (`routers/`) receive HTTP requests, call the CRUD layer, and map errors to status codes.
- **Schemas** (`schemas.py`) validate input before anything reaches the database.
- **CRUD layer** (`crud.py`) contains all database logic, including the duplicate-email check.
- **Models** (`models.py`) define the `students` table; SQLAlchemy writes to SQLite.
- **Lifecycle:** on startup the table is created if it does not exist.
  - *Create:* validate -> check email is unique -> insert -> return `201`.
  - *Update:* find student (`404` if none) -> validate -> check email uniqueness -> save.
  - *Delete:* find student (`404` if none) -> delete -> `204`.
